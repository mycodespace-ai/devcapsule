# Golden Platform Lock Fixtures

## Purpose

This directory holds byte-exact reference captures of the `linux-amd64` platform locks rendered by `MATRICES[Platform.LINUX_AMD64].resolve(need).render_lock()` for the representative capability sets (`GOLDEN_NEEDS`) defined in `tests/integration/test_resolution_matrix.py`.

These fixtures serve two testing roles:

1. **Resolution & Serialization Regression (`test_resolution_matches_the_captured_golden_lock`):** Verifies that capability normalization, provider and base selection, scoped capability digest calculation, component metadata formatting, and deterministic TOML lock rendering remain byte-identical unless a catalog pin or lock schema deliberately changes.
2. **Realistic Lock Inputs for Configuration Tests (`tests/integration/test_capability_minimums.py`):** Supplies realistic multi-component lock documents (such as `intellij-browser.lock` and `codium-agents.lock`) for checkout composition, trust channel, and historical schema-compatibility checks without re-encoding catalog pins inside individual test modules.

## Regenerating the Fixtures

Whenever an intentional change advances `_MATRIX_VERSION` or updates a `linux-amd64` base or component pin in `devcapsule/resolution_matrix.py`, regenerate all fixtures in this directory in the same commit from `devcapsule-src/`:

```bash
.venv/bin/python scripts/regenerate-golden-locks.py
```

`scripts/regenerate-golden-locks.py` imports `GOLDEN_NEEDS` and `GOLDEN_ROOT` directly from `tests/integration/test_resolution_matrix.py` so the fixture set and the integration test cannot drift.

## File Format (`devcapsule-lock-format-version = 1`)

Each `.lock` file is a deterministic, restricted-shape TOML document (string, integer, boolean, and string-list scalars plus nested tables in insertion order) rendered by `Formation.render_lock()`:

1. **Header Comments:**
   - Two provenance comment lines naming the embedded resolution matrix version:
     ```toml
     # Generated by 'devcapsule project init' from the embedded resolution matrix embedded-36.
     # Commit this file: it pins the exact environment collaborators receive.
     ```
   - For experimental (`--unverified`) resolutions, a third comment line lists the unvalidated pairs (`# WARNING: an experiment. Not yet validated: ...`).
2. **Top-Level Scalars:**
   - `devcapsule-lock-format-version = 1`: lock schema version.
   - `resolution-matrix-version = "embedded-36"`: informational identifier of the embedded matrix that generated the lock (`R-COMPAT-001`).
   - `platform = "linux-amd64"`: target capsule platform (`Platform.value`).
   - `capabilities-digest = "<sha256>"`: canonical SHA-256 digest of the normalized capability requirements (`{"need": [...]}`).
   - `unverified-combinations` *(optional)*: semicolon-separated list of unvalidated component/base pairs when resolved with `allow_unverified=True`.
3. **`[base]` Table:**
   - `reference`: digest-pinned OCI base image reference (`docker.io/mycodespaceai/devcapsule-base@sha256:...`).
   - `build-mnemonic`: builder identity mnemonic (for example, `"v0.3.0-local-linux-x86_64"`).
   - `contract`: base family and recipe version (for example, `"ubuntu-24.04@11"`).
   - `recipe-source`: repository path of the base image recipe.
4. **`[components]` Table and `[components.<component-id>]` Subtables:**
   - `interactive-surface`: component ID of the selected interactive IDE or terminal surface (`"pycharm"`, `"intellij"`, `"rider"`, `"eclipse"`, `"codium"`, `"vscode"`, or `"xfce4-terminal"`).
   - `[components.<component-id>]`: exact pinned lock fragment for the surface and each resolved ancillary component, including:
     - `version`, `delivery-policy` (`"local-materialization"` or `"base-image"`), and `license`.
     - Direct archive fields (`url`, `sha256`, optional `variant`, `upstream-sha512`, `npm-package`) or per-platform/multi-artifact subtables (`[components.<id>.artifacts...]`, `[components.<id>.native-packages.<pkg>]`, `build-recipe`).
     - Vendor consent metadata (`acquisition-authorization`, `terms-url`, `distribution`) for user-acquired proprietary components (`antigravity-cli`, `claude-code`, `vscode`, `rider`, `eclipse`).
5. **`[materialization]` Table:**
   - `recipe` and `recipe-version`: surface materialization recipe used to unpack and configure the interactive surface layer (`"jetbrains-local-materialization"`, `"vscode-local-materialization"`, `"eclipse-local-materialization"`, or `"xfce4-terminal-deb"`).
